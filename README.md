# SBOM generator 
Generates an SBOM as a CSV and a JSON file in the specified directory by traversing subdirectories and examining requirements.txt, package-lock.json and package.json files.

The SBOM includes the following columns:
- Name
- Version
- Type (npm or pip)
- Absolute path to where the dependency was found
- Scope (Production, Development or Unknown)
- Git commit hash of the source code repository

## How to run
Run the sbom.py file using Python 3 with a directory containing one or more Git repositories as argument, for example:
```
python3 sbom.py /home/Johannes/code/repos/
```

## How to test
The repository contains a test_repos directory with example requirements.txt, package.json and package-lock.json files. It also contains example_sbom.csv and example_sbom.json which show the output generated by the program and can be viewed directly on GitHub.

To test the program using the test_repos directory clone the repository and run the command:
```
python3 sbom.py /path/to/repos/sbom/test_repos/
```
and replace /path/to/repos/ with the path to the cloned repository.

## Assumptions and limitations
- Assumes dependencies inside requirements.txt are managed by pip and dependencies inside package.json and package-lock.json are managed by npm.
- Dependencies inside requirements.txt have scope set to 'Unknown'.
- Assumes requirements.txt files follow the format "name==version".
- Assumes package-lock.json files use lockfile version 3.
- If a package-lock.json file is found in a repository, the SBOM generator uses it instead of the package.json file to generate the dependencies. From the npm docs: "As of npm v7, lockfiles include enough information to gain a complete picture of the package tree, reducing the need to read package.json files". (https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json)

## Future improvements
- Support lockfile version 1 and 2.
- Identify outdated dependencies.
- Identify dependencies with known security vulnerabilities.
